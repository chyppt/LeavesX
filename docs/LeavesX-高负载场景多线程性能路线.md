# LeavesX 高负载场景多线程性能路线（R1 起）

本路线承接《区域化多线程开发方案》R0（已交付：流水线骨架、线程域守卫、intent 设施、降级参数、诊断）。目标场景由运营方向确定为**高负载、超多实体、区块与玩家高并存的生电服务器**。量化目标：**达到 Folia 同场景 ≥50%、Leaf ≥80% 的吞吐（TPS/MSPT p50）**，全程不破坏任何 Paper/Bukkit API 与生电特性；每次性能验证以固定场景实测为准，不承诺百分比。

## 一、目标场景画像与热点分布

高负载生电服的 MSPT 大头（按既有诊断与 Paper 社区共识，需在 R1 前用 `/leavesx hotspots`、spark 在目标存档实测校准）：

| 热点 | 典型占比 | 现状 | 区域化相关 |
| --- | --- | --- | --- |
| 实体 Tick（AI/寻路/移动/碰撞） | 35–55% | 已并行：AI 排序/激活/追踪差量/水中寻路（实验）；陆地寻路、推挤求解在主线程 | R1–R3 主战场 |
| 区块管理（加载/卸载/序列化） | 10–25% | 卸载加速、打包异步；存档序列化在 Tick 线程 | R2/R4 |
| 刷怪统计与自然生成 | 5–15% | 已并行统计 | 区域内天然并行 |
| 随机刻/计划刻/流体 | 5–15% | 随机刻坐标缓存（未并行） | R2 |
| 红石/TNT/方块更新 | 10–20% | 原样（生电红线，永不异步化） | 区域内串行保序 |
| 事件/插件 | 场景差异大 | skip-empty-events | 串行提交相位 |

生电服的关键事实：装置（刷怪塔、TNT 阵列、机器群）通常空间上聚簇且彼此远离——**这正是区域化收益最大的形态**：多个装置区天然成为独立区域并行执行，而每个区域内部保持原版串行序，特性零破坏。R1 的「并行世界」对单世界生电服无收益，因此 R1 与 R2 的推进速度决定达标时间。

## 二、风险分级的优化清单（全部走 leavesx.yml 配置）

### 低风险（默认开启候选，保真由构造保证）

1. **L0 区块存档序列化下线程**（原 M5）：主线程冻结引用 → 计算线程序列化 NBT → I/O 池写盘。不改变游戏逻辑，只移动时机。验收：崩溃注入 + 重启逐字段比对 + 自动保存窗口 MSPT 对比。
2. **L1 POI/寻路查询冻结视图复用**：村民找工作、蜜蜂归巢等 POI 扫描使用已有的快照设施批量提交，替换逐实体重复扫描。验收：结果与逐个扫描一致的对拍。
3. **L2 实体激活/目标计算共享快照**（原 M3）：一 Tick 一次基础实体快照（primitive 数组），激活、AI 排序、追踪差量共用，消除重复快照构建。bit-exact 验收。
4. **L3 光照/信标分配池化**（已有 0296 延伸）：将 Batch attorney 下的临时分配接入计算池的回收站，纯分配优化无语义面。

### 中风险（experimental → 连续两个 beta 零回退 → 默认）

5. **M1 地面寻路快照**（原 M2）：陆地 NodeEvaluator 冻结清单（方块数据/PathType 表/流体标签/光照 nibble）+ 后台完整搜索 + 采用前复核。这是超多实体场景单项收益最大的优化。风险点：自定义 NodeEvaluator、动态代价源——全部走排除路径回主线程。
6. **M2 高密度推挤完整并行**（原 M4）：分片有序对 + 主线程按索引序累加；有推挤相关事件监听器时整批回退。刷怪塔掉落物 1–2 万场景直接受益。
7. **M3 区域化区块 Tick（R2）**：随机刻（每区块独立派生 RNG，天然安全）、计划刻、流体按区域并行。风险点：跨区域方块更新序——intent 化 + 对拍矩阵（固定种子世界逐 Tick 方块哈希）。
8. **M4 并行世界（R1）**：跨世界传送/门户 intent 化，原版世界序应用。多世界服直接受益；单世界服无回归风险（单区域时退化为原路径）。

### 高风险（永不默认，门禁最严）

9. **H1 区域化实体 Tick（R3）**：本路线的收益顶点。超多实体生电服的实体 Tick 占比过半，只有 R3 能把它并行化。前置：R2 稳定发布一个版本 + 生电回归包双跑 0 分叉。事件顺延规则保证插件零破坏；刷铁机、TNT 炮、零刻装置在单区域内时序不变由构造保证。
10. **H2 爆炸射线并行**：固定子种子派生 + 原序合并；TNT 阵列 bit-exact 不达标即放弃。

## 三、风险消除机制（对应每类风险）

| 风险类型 | 消除手段 |
| --- | --- |
| 数值/时序偏差 | 对拍框架产品化：注册式接入，固定种子世界 on/off 双跑，逐 Tick 哈希（实体 NBT/位置、方块 tick、RNG 游标），分叉即定位首个 intent |
| 插件线程契约 | 不变量 A（插件只在 SERVER 线程、世界静止时可见）；ThreadDomain 断言开发构建 fail-fast；发布守卫禁止 threadedregions 引用 |
| 不兼容插件 | strict-serial-worlds 混合部署；`mode: off` 永久回退面 |
| 性能反噬 | 断路器（屏障超时 25%、重放阈值 64）自动降档 regions→worlds→off；`/leavesx safety` 可观测 |
| 存档损坏 | 序列化只在世界静止相位发起，原子替换，崩溃注入测试 |
| 未知边界 | 每个中风险项默认 experimental 且附带排除清单；真实服 soak 一个 beta 周期零降级才转默认 |

## 四、里程碑与达标路径

| 阶段 | 内容 | 预期收益（高负载生电，相对 Leaf） |
| --- | --- | --- |
| R1（beta7） | M4 并行世界 + M1/L0/L1/L2 低中风险优化 | 多世界服接近 Leaf 并稳超；单世界服 ~85–90% |
| R2（beta8） | M3 区域化区块 Tick + M1 地面寻路转正 | 单世界多装置区：区块/刷怪/寻路并行化，~95% |
| R3（beta9–beta10，experimental） | H1 实体区域化 + M2 推挤转正 | 实体 Tick 并行，跨装置区并行执行，≥100%（即达成并超越 Folia 50% 目标，因为 Folia 本身受插件串行相位拖累而 LeavesX 无此成本） |
| 1.2.0-rc | 默认值翻转（双 beta 零回退后）+ 全量回归 + 文档 | — |

50%/80% 目标的达成判定：固定基准集（相距 1000 格双装置区各 2k 实体、2 万掉落物堆叠、自动保存窗口、传送风暴）上，LeavesX TPS ≥ Folia×0.50 且 ≥ Leaf×0.80，MSPT p99 不劣于 Leaf×1.10。基准脚本与结果进 `build/reports/`，每个 beta 留档。
