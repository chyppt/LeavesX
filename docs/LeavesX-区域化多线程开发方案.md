# LeavesX 区域化多线程开发方案（并行模拟 · 串行可见）

本方案是《LeavesX-多线程后续开发方案》的方向升级：不再以快照纯计算为主线，而是引入趋近 Folia 的区域化并行 Tick，同时把「不破坏任何 Paper/Bukkit API、不改变任何游戏特性」作为硬约束。原方案中的快照路线不废弃——降级为区域内部的纯计算优化与区域化关闭时的回退实现。适用分支 `leavesx/26.1.2`，补丁序号从 0308（paper 侧 0229）继续。

## 0. 定位与核心判断

Folia 插件不兼容的根本原因不是线程数量，而是它改变了插件线程契约：事件在区域线程触发、`Entity.getScheduler()` 要求插件自查归属、跨区域 API 访问直接抛异常。要同时满足「并行度趋近 Folia」和「插件零改动、零破坏」，只有一种架构成立：

> **并行模拟、串行可见**：游戏模拟（实体、方块、流体 Tick）在区域线程上并行执行；插件可见的一切——Bukkit/Paper 事件、调度器任务、API 调用——只在唯一的 SERVER 线程上发生，且发生在所有区域都已到达屏障、世界静止的串行提交相位。

由此得到两条不变量，任何补丁违反即回退：

- **不变量 A（插件可见性）**：插件代码只在 SERVER 线程执行，执行时世界处于静止一致状态。插件无法通过任何合法 API 手段区分 LeavesX 与 Paper 的线程行为。
- **不变量 B（游戏语义）**：区域内保持原版串行顺序；跨区域效果以 intent 在屏障相位按原版全局遍历序应用；空间上连通的加载区自动合并为单一区域。生电装置所在区域的行为与单线程逐项一致。

代价与上限（诚实声明）：这不是 Folia 的「插件也并行」。事件密集的服务器收益有限（它们本来就受事件处理约束）；屏障与 intent 队列有固定开销；性能上限低于彻底区域化。这是两个硬约束下唯一自洽的解。

### 第零原则

稳定与安全优先于一切性能目标，具体为四条：

1. **正确性优先**：任何吞吐、延迟收益都不构成降低安全标准的理由；不变量 A/B 与 §5 全部门禁优先于路线图进度。
2. **默认保守**：一切新并行路径默认关闭；`mode: off` 是永久回退面，任何版本、任何时刻可无损退回，无需配置迁移、不涉及存档格式。
3. **不可观测不发布**：每个新机制必须自带降级计数与诊断输出；无法观测的特性不进入发布。
4. **可回滚**：旧执行路径与新路径共存至少两个稳定版本；回滚只改配置，不回退存档、不清理数据。

## 1. 架构总览

### 线程域

| 线程域 | 数量 | 执行内容 | 禁止事项 |
| --- | --- | --- | --- |
| SERVER | 1 | 插件代码、全部 Bukkit/Paper 事件、调度器任务、全局状态（计分板、命令、天气、时间）、串行提交相位 | — |
| REGION | 0..N | 本区域的实体/方块/流体/POI 模拟（原版代码路径） | 触发事件、调用插件代码、触碰非本区域状态、跨区域锁 |
| COMPUTE | 已有计算池 | 纯数学分片（激活、AI 排序、追踪差量等，现有设施不变） | 同现状 |
| IO | 已有 I/O 池 | 存档、打包（现有设施不变） | 同现状 |

### Tick 流水线

```text
每 Tick:
  Phase 1 并行模拟
    各 REGION 线程按原版顺序推进本区域实体/方块/流体/计划任务
    - 无监听器的事件: inline 跳过（复用 skip-empty-events）
    - 有监听器的事件: 记录为 deferred event intent，该实体本 Tick
      剩余逻辑一并顺延到 Phase 3（避免在事件结果未知时继续推断）
    - 跨区域效果（伤害、传送、骑乘、方块更新越界）: 记录为 cross-region intent
  Phase 2 屏障
    全部区域到达，世界静止
  Phase 3 串行提交（SERVER 线程，世界静止）
    按「原版全局遍历序」应用全部 intent：跨区域状态变化、
    重放 deferred 事件（触发 Bukkit/Paper 事件与插件回调）、
    执行顺延的实体剩余 Tick、Bukkit 调度器任务
  Phase 4 并行后处理
    实体追踪差量、区块打包、网络编码（现有 async 设施，不变）
```

事件顺延规则是本设计的自适应关键：**只有存在监听器的事件才触发顺延**。生电服（几乎无实体事件监听）获得完整并行；插件重的服务器自动退化为接近现状的串行——不会更差。

### 顺序确定性

Vanilla 在单线程下按固定的实体列表序与区块序遍历。区域化执行保持该语义的手段：

- Tick 开始时把实体列表按区域切片，**切片保持全局列表原序**（复用现有 LeavesX 分片纪律，主线程一次性完成，无锁）。
- 每个 intent 携带 `(全局列表位置, 局部序号)`。
- Phase 3 按区域在原全局序中的展开顺序重放，同区域内按局部序号。
- 对拍框架逐 Tick 校验该序与单线程运行一致（见 §5）。

## 2. 区域模型

### 划分

- 区域 = 一个世界内加载 ticking 区块的**连通分量**；空间间隔小于合并半径（默认 8 区块，可配）的分量合并为同一区域。
- 区域图在票据变化时于 Tick 边界增量重算（摊销，不在关键路径），借鉴 Folia regionizer 但实现从简：固定网格聚合 + 连通合并，不追求 Folia 的动态迁移精度。
- **关键性质：一个连续加载区（典型生电服的主城 + 全部装置）天然属于单一区域，其 Tick 就是今天的单线程路径。** 特性保真由构造保证，不靠逐装置验证。

### 所有权

- Chunk、区块内方块状态、区域内实体、区域内 POI → 归属 REGION，单写者。
- 玩家实体 → 归属其所在区域（R4 前玩家 Tick 仍在 Phase 1 区域线程执行，数据包处理 v1 保持串行相位，见 §4）。
- 计分板、BossBar、命令树、世界时间/天气、advancement 全局状态 → SERVER，只在 Phase 3 读写。
- 跨区域实体移动（走出区域边界）→ intent，Phase 3 转移所有权；实体数据包可见性由 Phase 4 追踪差量处理。

### 跨区域交互

- 伤害、交易、碰撞、骑乘、栓绳、流体/方块更新越界 → cross-region intent，本 Tick Phase 3 应用（不是下一 Tick，保证机制时序）。
- 相邻基地边缘高频互动的场景会产生产能损失 → 由合并半径兜底（互动密集的加载块自动归同区域）。
- POI 跨区域查询（村民找工作点等）→ 走已有快照/计算池设施读冻结视图，或 Phase 3 串行读取；村民完整逻辑维持 villager-compatibility 约束不变。

## 3. API 与特性兼容层

- **事件**：全部 Bukkit/Paper 事件只在 SERVER 线程、Phase 3（或无监听器时 inline 跳过）触发。事件顺序与单线程一致（§1 顺序确定性）。
- **调度器**：`Bukkit.getScheduler()` / Folia scheduler API（`getRegionScheduler()`、`Entity.getScheduler()`、`getAsyncScheduler()`）全部映射到现有执行域——同步任务到 SERVER，异步任务到通用池；不引入「插件必须自查线程」的新契约。插件无需声明 `folia-supported`。
- **`Bukkit.isPrimaryThread()`**：仅 SERVER 线程返回 true，语义与 Paper 完全一致。
- **线程守卫**：扩展 Paper 的非法线程检查到 REGION 线程——原版代码路径误触插件/事件调用时 fail-fast（回归安全网，只影响 LeavesX 自身代码质量，不影响插件）。
- **strict-serial 兜底**：`strict-serial-worlds: []` 允许把指定世界（或全部）钉死在 SERVER 线程 Tick。装了 NMS 反射型/静态状态型不兼容插件时，可混合部署（如主世界串行、空岛世界并行）。这是对不遵守 API 契约的插件的唯一救济手段，官方不承诺更多。
- **进阶（后期，非承诺）**：plugin.yml 可选声明 `leavesx-region-threaded: true`，允许该插件的监听器在区域线程执行，换取 Folia 级事件吞吐。默认关闭，不在首期路线内。
- **与现有设施关系**：compute lanes、快照预算、优先级车道（原方案 M1）照常建设——区域化关闭时它们是全部收益来源，开启后服务区域内热路径与 Phase 4；async 区块打包、玩家存档 I/O 不变。

## 4. 分阶段路线

### R0 线程域与流水线地基（0308–0311 / paper 0229–0232）

- ThreadDomain 标记、断言与守卫；Tick 循环重构为四相位流水线（区域数为 0 时空转屏障，行为与今日 bit-exact）。
- intent 队列、屏障、全局序重放器的通用实现与单元测试。
- `regionized-ticking` 配置骨架（`mode: off`）+ `/leavesx regions` 诊断（区域图、各区域 MSPT、intent 吞吐、屏障等待、顺延计数）。
- 原 M1 的优先级车道与快照预算并入本阶段。

### R1 并行世界（0312–0315 / paper 0233–0236）

- Phase 1 按世界并行执行（世界 = 最粗粒度区域）；跨世界实体/方块效果 intent 化，Phase 3 按原版世界序应用，保证跨维度机制（传送门、末影珍珠）时序不变。
- 全部事件仍主线程；数据包处理不动（仍在串行相位）。
- 单世界服零变化；验收后 `mode: worlds` 可转默认开启候选。
- 当年文档拒绝 parallel-world-ticking 的理由（插件假设单线程）恰好被本架构的事件串行化解决——R1 是对该决策的受控翻案。

### R2 区域化区块 Tick（0316–0320 / paper 0237–0241）

- 随机刻、计划刻、流体按区域并行；区域内保持原版区块序与逐方块 RNG 序（随机刻每区块独立派生，天然适配）。
- 跨区域方块更新 intent 化；零延迟更新链（更新抑制器、零刻装置）在单区域内行为不变。
- RNG 审计：清点被迁移路径引用的全部 RandomSource，跨区域共享序列（如 level 级共享随机）改为按原版序在屏障相位消耗或按原种子派生子序列。
- 对拍：固定种子世界逐 Tick 方块状态哈希一致。

### R3 区域化实体 Tick（0321–0328 / paper 0242–0249）

- 实体列表按区域切片（保全局序），区域线程执行完整实体 Tick；有监听器事件触发顺延（§1）；跨区域伤害/传送/骑乘/死亡掉落 intent 化。
- 村民、TNT、红石路径只在区域内并行，逻辑本身不变（villager-compatibility 继续生效）。
- 移植对拍矩阵（节点/顺序/代价/计数逐项一致）+ 生电回归包（TNT 炮、复制机、刷铁机、更新抑制器、零刻）。
- `mode: regions` 进入 experimental。

### R4 收敛（0329+ / paper 0250+）

- 可选：玩家数据包按归属区域在 Phase 1 处理（进一步并行化网络→模拟路径）。
- timings/spark 的区域感知、每区域 MSPT 报告；基准场景留档；默认值策略（experimental → 默认，需连续两个 beta 零回退零对拍偏差）。

阶段推进严格执行 §5.4 门禁：R2 的开发前置是 R1 稳定发布一个版本，R3 的前置是 R2 稳定发布一个版本；任何门禁不满足即停在当前阶段，不并行抢进度。

## 5. 安全与稳定性保障体系（纵深防御）

### 5.1 设计期（Layer 1）

- 不变量 A/B 是代码评审的硬检查项；区域线程之间禁止锁，只允许并发队列 + 屏障通信；单写者所有权是唯一的状态变更通道。
- intent 队列、屏障、全局序重放器等调度组件拥有独立单元测试与状态机测试，覆盖满载、乱序完成、重复投递、中途取消。

### 5.2 构建与开发期（Layer 2）

- ThreadDomain 断言在开发构建常开：区域线程一旦触达插件调用点或 Bukkit 事件触发点立即抛出（LeavesX 自身代码的回归安全网，不影响插件）。
- 双跑对拍框架：固定种子脚本世界，regionization 开/关双跑，逐 Tick 状态哈希（实体 NBT/位置/血量、方块 tick 数据、RNG 游标）比对；任何一 Tick 分叉即失败，并二分定位首个分叉 intent。
- 生电回归包与 9.5k+ 现有回归全绿是每个补丁合入前提，沿用现行纪律。

### 5.3 运行时自动降级（Layer 3，断路器）

降级只发生在 Tick 边界，逐级触发、逐级保守，不需要人工介入即可自愈回安全状态：

| 触发条件 | 动作 |
| --- | --- |
| intent 队列溢出 | 该区域本 Tick 串行重放（正确性优先） |
| 屏障等待持续超过 Tick 预算阈值 | 超时区域降级为 SERVER 线程 Tick，观察窗口后自动恢复 |
| 调度器异常（发生在该区域 Tick 开始前） | 该区域本 Tick 回退 SERVER 执行 |
| 单 Tick 内串行重放次数超阈值 | 自动降档 regions → worlds |
| 降档后仍持续溢出或超时 | 自动降到 off，原因写入日志与诊断 |

全部降级事件计数进 `/leavesx safety`；同类事件在滚动窗口内反复出现时，控制台醒目提示管理员检查（通常是插件行为或装置布局触发，需要 strict-serial 兜底）。

### 5.4 发布期门禁（Layer 4）

阶段推进的硬性标准，全部满足才继续，进度永远让位于安全：

- **G0（R0 合入）**：流水线开启与关闭在全部对拍世界 bit-exact；空转屏障开销在基准场景中 p99 MSPT 差异处于噪声内。
- **G1（R1 转默认候选）**：双跑对拍 0 分叉；≥2 个 beta 周期真实服 soak，0 次未解释降级；插件矩阵 0 回归。
- **G2（R2 启动前置）**：R1 已作为非 experimental 稳定发布至少一个版本；RNG 审计清单全部关闭。
- **G3（R3 启动前置）**：R2 稳定发布一个版本，且生电回归包双跑 0 分叉；R3 全程保持 experimental。
- **G4（任何模式转默认）**：连续两个 beta 零降级、零对拍分叉，外加真实服试点累计达标（服务器小时数阈值在发布文档中明确）。

### 5.5 故障遏制（Layer 5）

- 原版游戏代码在区域线程的异常与 Paper 主线程异常同等对待（watchdog 崩溃保存）；不尝试中途回滚有状态执行——代码路径与单线程完全相同，异常率不应有差异。
- 存档完整性：保存只在世界静止相位发起，文件原子替换；崩溃注入测试覆盖序列化中途与屏障中途，不允许半成品。
- 内存上界：intent 队列、快照预算（R0 并入）、区域数与线程数共享同一预算；极端负载下拒绝新工作并计数，不堆积。
- Watchdog 增加区域挂起与屏障超时检测；由于「无跨区域锁」规则，死锁在构造上不可能，watchdog 仅兜底调度器自身缺陷。

## 6. 风险清单

1. 屏障与 intent 开销在高事件密度服可能吞掉并行收益 → 事件顺延规则保证不劣于现状，但收益趋零。
2. 相邻高频互动的多基地区域产能受限 → 合并半径兜底，可配。
3. NMS 反射/静态状态插件 → 只提供 strict-serial-worlds 混合部署救济。
4. Folia 上游同步成本：本方案不引入 Folia 代码与 API，仅借鉴 regionizer 思想，Paper 补丁基线不受影响。
5. 工程量大：R3 完成前不应承诺任何时间点；每个 R 阶段独立可发布、独立可回退（`mode: off` 恒久保留）。
6. 止损原则：若 R3 长期无法满足门禁（对拍分叉无法归零、降级频发），路线停在 R1/R2 已交付的收益上，不强推实体区域化。高性能是目标，稳定安全是前提。

## 7. 验证与发布

- 基准场景（只报实测，不承诺百分比）：相距 1000 格双基地各 2k 实体、单基地区域（对照组，应与现状持平）、传送风暴、事件密集插件负载、自动保存窗口。
- 插件矩阵：EssentialsX、LuckPerms、WorldEdit/WorldGuard、Vault、PlaceholderAPI、spark、背包/经济类各选代表，开启 regions 模式跑功能冒烟。
- 生电回归包：TNT 炮与复制机、刷铁机、零刻/更新抑制器、村民交易所、实物流水线，双模式输出对比。
- 发布节奏：R0/R1 → beta6；R2 → beta7；R3 → beta8–beta9（experimental）；R4 → 1.2.0-rc。每阶段全套回归 + soak 真实服一轮。

## 8. 配置草案

```yaml
regionized-ticking:
  # 区域化并行 Tick 总开关。off 时全部走现有单线程 + 快照计算路径。
  mode: off            # off | worlds | regions
  # 空间间隔小于该区块数的加载分量合并为同一区域。默认 8。
  merge-radius-chunks: 8
  # 始终钉在 SERVER 线程 Tick 的世界列表（不兼容插件救济）。
  strict-serial-worlds: []
  # intent 队列上限，溢出区域该 Tick 串行重放。默认 65536。
  intent-queue-size: 65536
  # 自动降级：屏障等待占 Tick 预算比例持续超过该值时，超时区域降级为 SERVER 线程 Tick。0 关闭。默认 25。
  auto-degrade-barrier-percent: 25
  # 单 Tick 内串行重放累计超过该次数自动降档模式（regions → worlds → off）。0 关闭。默认 64。
  auto-degrade-replay-threshold: 64
  # 区域线程预算来自现有 parallelism.workers 同一预算，不新增总线程数。
  threads: 0           # 0 = 自动
```

`mode: off` 永远可用且是默认值；所有阶段共享这一回退面。
