# LeavesX 1.1.0-beta4

适用 Minecraft 26.1.2，Java 25。本轮继续拆分主线程工作，但没有将完整实体 Tick、完整寻路或方块更新改成异步。

## 新增后台计算

### 长跳 AI 候选准备

`async.ai-candidates` 默认开启。山羊、青蛙准备长跳时，独立生成候选坐标及权重；工作线程只接收不可变起点和搜索尺寸，不接收生物、世界或 Brain。候选遍历顺序和权重与原逻辑一致，随机抽取、落点检查、寻路、声音及跳跃状态修改仍在主线程。

任务在行为开始时提交，第一次使用候选时取得完整结果，不跳过 AI Tick。任务尚未完成时该处仍需等待；失败时用原输入完整重算，队列满时直接走原流程。小批量以及未经审核的行为子类保留同步执行。共用现有异步计算池，不另建线程池。

### 玩家存档压缩

`async.playerdata-save.compression` 默认开启，需要同时启用 `async.playerdata-save.enabled`。主线程采集玩家状态并深拷贝 NBT；后台执行二进制编码、压缩和写入。同一 UUID 的这些步骤在同一条有序队列上执行，避免后提交的小存档覆盖顺序倒置。读取玩家数据仍等待该玩家之前的保存完成。

快照会增加短时内存占用。该优化面向自动保存时的压缩负担，不会并行修改玩家、背包或插件对象。任务队列满时沿用原有保存背压，不能无限堆积。

### 大批简单碰撞盒计算

`parallelism.mob-collision-math` 为实验性开关，默认关闭。仅普通 Mob、至少 8,192 个简单 AABB、没有复杂体素形状时尝试并行；村民及所有非 Mob 实体均走原逻辑，因此 TNT、玩家、矿车、掉落物不使用此入口。

主线程收集形状，将不可变 AABB 引用复制后分片计算。Y 轴及随后 X/Z 轴的先后顺序不变，实际移动和台阶处理仍在主线程。碰撞容差造成位移跨零、出现非有限结果或计算失败时，该轴完整按原顺序计算，不拼接部分结果。

普通移动通常达不到该批量，不能把此开关理解成所有实体都在工作线程移动。线程调度、数组复制及同步均有成本，是否获益需要按实际场景测量。

## 配置与诊断

假人创建的作用直接放在名称后：`/bot create 111 测试`，支持中文及颜色字符；显示仍由 `fakeplayer.role` 的开关和校验控制。需要指定皮肤时使用 `/bot create 111 skin Notch 测试`。旧 `role` 写法保留为兼容别名，控制台原有“名称 皮肤 世界 坐标”脚本继续接受，坐标后也可以追加作用。实际账号名允许 3–16 个字母、数字或下划线，`111` 不再被四字符下限拒绝。

配置版本升为 79，旧值保留，新选项自动补全。新开关可通过 `/leavesx reload` 更新；计算池本身的启停继续遵循原重启要求。

`/leavesx threads` 新增“AI 长跳候选准备”任务统计；`/leavesx parallel` 的工作量分类新增“生物碰撞数值计算”。工作线程次数为零时，需要结合开关、批量及任务类型判断，不能仅凭配置已开启认定发生了并行。

## 仍保留主线程的机制

| 路径 | 当前边界与原因 |
| --- | --- |
| 完整寻路 | 节点计算器还读取实时生物、流体、碰撞上下文和区块。需要完整快照、失效校验及特殊生物适配，不能仅给 PathFinder 加锁。 |
| 完整 AI 与村民行为 | Brain、目标选择、职业占用、攻击及插件事件互相影响，仍按主线程顺序提交。命名生物的持久化逻辑不变。 |
| 实体移动和推挤 | 本版只并行部分包围盒数值计算；位置、速度、碰撞事件和推挤顺序不搬到后台。 |
| 漏斗和箱子转移 | 库存修改及 InventoryMoveItemEvent 必须保持交易式顺序，不能让两条线程同时修改同一物品堆。 |
| 红石、TNT、随机刻 | 更新会修改后续操作读取的方块、实体及随机数状态；整批预计算或重排执行会影响生电装置和随机机制。 |

这不是 Folia 的区域 Tick 模式。未做与生产存档或 Folia 的同负载对照，不承诺综合性能提升比例。

## 验证

多线程和配置变更的完整回归共 9,566 项，0 失败、22 项跳过。随后假人命令新增 4 项解析和名称边界测试，均通过；已额外确认这些测试纳入项目的 JUnit Suite。新增补丁通过反向检查及隔离目录重新应用后的逐文件比对。

完成启用新开关、关闭后重启、默认配置重启三轮真实服检查；每轮均执行配置重载、存档和正常关闭。默认配置示例见 [leavesx.example.yml](leavesx.example.yml)。

真实服启用新功能后，山羊和青蛙候选各完成一项后台任务；碰撞探针记录两次并行调用，共 16,384 项，其中 12,288 项由工作线程处理，结果与原计算一致。玩家存档覆盖连续保存、提交后修改源 NBT、立即读回等待等情况。该数据说明入口确实工作，不是性能提升比例。

假人验证覆盖玩家直接输入中文作用、旧控制台坐标语法、三字符用户名、作用保存和 TAB 显示；开启与关闭作用显示均保持真实名称不变。

TNT 复制探针生成 30 个 TNT，初速度、首 Tick 位移及爆炸触发检查通过，原结构的 10 个 TNT 方块保留。探针取消爆炸事件以保护结构，未覆盖所有 TNT 炮。命名僵尸、掠夺者、村民和末影螨的远距离保留及重启读取检查通过。测试日志保存在 `build/reports/beta4`。
