# LeavesX 多线程扩大路线（beta8+）

beta7 后主线程剩余热点重新扫描完成。本文把路线扩大为四个梯队共 16 项：两个梯队保持低风险（延续 beta7 纪律，全部行为等价类），中风险梯队进入快照式并行（复用已验证框架），高风险梯队维持门禁。所有 Leaf 移植内容照例在配置注释标注来源与许可。

## 热点扫描结论（本轮新发现）

| # | 路径 | 现状 | 评估 |
| --- | --- | --- | --- |
| 1 | TNT/爆炸射线（ServerExplosion） | 主线程逐射线步进 + Paper 缓存已很激进 | 中风险：射线间独立，但 RNG 序与方块交互序是生电红线，默认放弃并行，只做分配优化 |
| 2 | 网络包处理（64 个 handler） | 主线程逐包 | 高风险：Folia 也只做了解码并行；处理回调共享世界状态，不碰 |
| 3 | 星光光照引擎 | 已有批处理/去重优化 | 中风险：跨区传播天然全局，分层并行需全链对拍，收益依赖场景，列观察项 |
| 4 | 漏斗推送 | 已有槽位缓存/直接扫描（Lithium 路径） | 低风险残留项：合并冷却 map 与物品查询缓冲池化 |
| 5 | 配方匹配 | 逐配方遍历 + hint | 低风险：按输入材料建索引查表，行为等价 |
| 6 | 掉落物合并扫描 | 已有 item-merge 停扫 | 低风险残留：合并候选配对半径排序复用 |
| 7 | 实体移动/碰撞 | Paper 碰撞已优化 + LeavesX 密集推挤 | 中风险见 M2（推挤完整并行） |
| 8 | 玩家存档压缩 | 已异步（beta2） | 无剩余主线程成本 |
| 9 | 区块状态升级（worldgen 执行器） | moonrise 线程池 | 已并行，不碰 |

## 梯队一：低风险行为等价（beta8，全部默认开）

**B1 配方匹配索引**：`RecipeManager.getRecipeFor` 在无 hint 时按输入类型线性扫全部配方。建立「输入材料组 → 候选配方列表」的不可变索引（RecipeManager 初始化后构建，插件注册配方时失效重建），匹配从 O(全部配方) 降到 O(候选)。不改匹配顺序——索引按原注册序排列，找到的第一个即原结果。开关：`performance.crafting.recipe-index`。

**B2 漏斗冷却与查询池化**：HopperBlockEntity 的转移冷却 map 与物品实体查询列表接入实例级复用（同 beta7 传感器模式，方块实体实例私有）。开关：`performance.block-entity.hopper-buffer-reuse`。

**B3 掉落物合并排序复用**：物品合并扫描的候选距离排序接入 StableDistanceSorter 的现成工作区（已复用），补齐配对半径预筛（超出半径直接跳过 distSqr），无新开关（item-merge 开关覆盖）。

**B4 `AbstractContainerMenu.quickcraftSlots` 复用**：创造模式批量拿取每 Tick 重建 HashSet，改为 clear() 复用（容器实例私有）。开关：`performance.blocks.quickcraft-set-reuse`。

## 梯队二：低风险并行增强（beta8）

**B5 计算池 work-stealing 尾延迟收窄**：现有 invokeRanges 的尾部领取在分片数≈线程数时仍有长尾；把领取宽度从固定值改为自适应（按剩余分片均值），沿用现有对拍。

**B6 追踪差量批间并行**：实体追踪（ENTITY_TRACKING）在 worlds 模式下按世界天然并行；单世界内把「收集变更」与「编码 diff」拆为流水两段（收集在 Tick 线程、编码进计算池），编码是纯读已冻结数据。开关：`async.entity-tracker.pipeline-encode` 默认开。

## 梯队三：中风险快照并行（beta9–beta10，experimental → 双 beta 零回退 → 默认）

**M1 陆地寻路快照**：水中寻路框架扩展。冻结清单：压缩方块段、PathType 预计算表、流体标签、光照 nibble（按需）。排除：栓绳、载具、自定义 NodeEvaluator、动态代价源。对拍矩阵逐节点一致 + 真实服 48 小时对照。

**M2 高密度推挤完整并行**：有序对分片 + 主线程索引序累加；推挤事件监听器存在即整批回退。对拍=串行逐对一致 + 2 万掉落物 MSPT 报告。

**M3 POI 批量冻结视图**：村民找工作/SetClosestHome 的 findAnyPoiPositions 已非加载（beta7），进一步把整村批量扫描（多村民同 Tick 同区域）合并为一次遍历、按村民分发结果——主线程一次构建不可变候选集，各村民筛选。等价验收=逐村民结果一致。

**M4 星光光照分层并行（观察项）**：先在目标存档测量光照 MSPT 占比；低于 3% 直接关闭此项不做。达标才进入全链对拍。

## 梯队四：高风险（不承诺，门禁最严）

**H1 R3 实体区域化**：前置= M1–M3 稳定发布一版 + 固定种子世界对拍 0 分叉。
**H2 爆炸射线并行**：TNT 装置 bit-exact 不达标即永久放弃。
**H3 网络解码并行**：仅在出现瓶颈证据时立项（解码在 Netty 线程本已并行，主线程只是 handler 分发；除非诊断证明分发成本，否则不动）。

## 排期与验收纪律

- beta8：B1–B6（全部低风险，一次交付，全量回归 + 每 ASM/行为测试与 beta7 同规格）。
- beta9：M1（旗舰，单独一个版本以便 soak）。
- beta10：M2 + M3；M4 视测量决定是否立项。
- 每项：默认 experimental 或行为等价默认开 → 全量回归 0 失败 → ASM 结构守卫 + 行为等价测试 → 真实服 soak 一个 beta → 双 beta 零回退才评估扩大默认面。中风险项任何对拍偏差即回退。

## 红线（不变）

事件、调度器、`isPrimaryThread` 语义不动；TNT/红石/村民恐慌/刷铁机逻辑不异步化；所有 Leaf/Paper 上游移植在配置注释标注来源与许可；`mode: off` 与各开关关闭永远完整回退到原版路径。
