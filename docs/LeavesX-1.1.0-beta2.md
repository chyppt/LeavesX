# LeavesX 1.1.0-beta2

适用 Minecraft 26.1.2，使用 Java 25。配置继续分为 `leaves.yml` 和 `leavesx.yml`。

## 本轮变更

- 区块打包使用独立队列。从已有异步线程预算分配工作线程，减少多人传送、进服时对其他计算任务的排队影响。
- 借鉴 Leaf 的容器同步实现，复用物品副本供给器，减少逐槽创建临时对象；插件回调重入时使用独立副本，异常退出时释放引用。
- 为已有 Lithium 优化增加总开关，控制漏斗槽位缓存、空闲挥手和滑翔状态检查。
- 可选虚拟聊天线程，默认关闭。聊天事件、同步插件调度的执行语义保持原有方式。
- 新世界可启用独立安全种子，默认关闭。结构、资源装饰、强要塞与史莱姆区块使用独立随机流，基础地形仍使用世界种子。
- `/leavesx ai` 发放 OP 专用木棍，右键切换生物 AI。村民关闭普通 AI 后仍可交易，在工作时间、工作站有效且距离足够近时按原每日限制补货，并触发 Bukkit 补货事件。状态随实体存档保存。
- 修复 `/player` 启动注册检查；`/leavesx` 命令和补全仅 OP 可用，打开 GUI 后失去 OP 也不能继续刷新诊断。
- 配置版本升为 77。版本号、性能、异步、并行配置在前，假人和消息配置在后；迁移保留用户已有值。

## 新配置

以下为新增配置的默认值，不是完整配置文件：

```yaml
performance:
  lithium:
    enabled: true
  container-copy-reuse: true
async:
  isolate-chunk-packing: true
  virtual-chat: false
features:
  secure-seed: false
```

`/leavesx reload` 重载配置；更改需要重启的选项时显示提示。上述区块队列隔离、虚拟聊天线程、安全种子选项需要重启。

安全种子仅影响启用后创建的新世界。旧世界不会被转换；已经启用的世界关闭配置后也继续使用保存的密钥，避免后续区块改变生成规则。密钥保存在世界数据中，请随世界备份。该实现借鉴 Leaf/Matter 的独立种子思路，使用 HMAC-SHA256，不兼容其种子格式，也不保证隐藏基础地形种子。

## 多线程边界

工作线程用于已隔离的数据计算，事件、实体状态修改与结果提交仍在主线程。区块打包、刷怪统计、实体追踪计算等保留异步能力。

旧寻路任务直接读取实时生物和区块，不能保证安全。本轮将这条寻路入口恢复为主线程执行；`async.pathfinding.enabled` 保留兼容，诊断会明确显示保护状态。目标距离计算仍可并行。这不是完整异步 AI，也不是 Folia 的区域 Tick 模型。

## 验证

完整测试共 9,547 项，9,525 项通过、22 项跳过、0 失败。包含配置迁移、并行失败回退、拥堵时计算队列隔离、容器回调重入与异常路径、AI 木棍权限和安全种子确定性测试。

隔离实例已验证启动、命令、重载、保存和正常关闭；村民补货及插件取消补货事件；AI 状态保存、重启读取、重新启用；安全种子新建世界、结构定位、史莱姆 API，以及关闭新世界开关后的存档重启一致性。测试日志保留在 `build/reports/beta2`。

另运行两轮现有 TNT 复制机探针：每轮复制 30 个 TNT，初速度、首 Tick 位移及爆炸触发检查通过，结构中的 10 个 TNT 方块保留。爆炸事件由测试插件取消以保护测试结构，不代表覆盖所有 TNT 炮场景。

尚无同一存档、插件、玩家负载下与 Folia 的对照结果，不能据此给出综合性能提升比例。真人客户端、特定插件组合和长期运行仍需实际服务器验证。

## 来源

- Leaf：容器同步复用方案（HaHaWTH 的 `Reduce AbstractContainerMenu allocations`），独立异步队列、可选虚拟聊天线程的设计参考。
- Lithium：已有漏斗与空闲实体热路径开关管理。
- Leaf/Matter：独立安全种子思路；本轮随机流和存储格式由 LeavesX 独立实现。
