# LeavesX 多线程能力盘点与下一批计划（beta7 起）

## 一、当前已多线程化的路径（截至 beta6）

### 并行世界 / 区域化（regionized-ticking，实验性）
| 能力 | 线程 | 状态 |
| --- | --- | --- |
| 四相位流水线（模拟→屏障→串行提交→后处理） | 服务器 + 世界线程 | 已交付（R0） |
| worlds 模式：非 strict 世界并行 Tick | 每世界一个 TickThread 执行器 | 已交付（R1，实验性） |
| 同步事件闸（插件代码保持在服务器线程） | 事件泵在屏障窗口 | 已交付（R1） |
| regions 模式 | — | 配置可解析，本版降级 worlds |

### 纯计算池（parallelism.*，稳定）
AI 目标排序/归并/选择、实体激活范围 AABB、实体追踪差量、刷怪统计、生物碰撞数值（实验）。

### 异步 I/O 池（async.*，稳定）
区块打包/发送（独立队列隔离）、玩家存档压缩与写盘（按 UUID 串行）、水中寻路快照搜索（实验）、长跳候选准备。

### 已知死锁修复（beta6 最终 jar）
屏障等待期间服务器线程持续泵送事件闸，消除「世界线程等事件分发、服务器线程等世界完成」的互等窗口。

## 二、主线程剩余大头（高负载生电服，按收益排序）

| 路径 | 现状 | 可否多线程 | 方案 | 风险 |
| --- | --- | --- | --- | --- |
| 陆地寻路 | 主线程完整搜索 | **可以** | 复用水中寻路快照框架：主线程冻结 PathType 表/方块数据/光照 nibble → 后台 A* → 采用前复核 | 中（排除清单兜底） |
| 高密度推挤 | 查询并行、求解串行 | **可以** | 有序对分片算增量 → 主线程按索引序累加 | 中（事件监听器回退） |
| 区块存档序列化 | Tick 线程序列化 | **可以** | 屏障相位冻结引用 → 计算线程序列化 → I/O 池写盘 | 低（不改逻辑只移时机） |
| 随机刻 | 主线程逐区块（已有坐标缓存） | **可以（worlds 内天然并行）** | 随机刻跟随世界 Tick 已随 R1 并行；单世界内按区域分片需 R3 | — |
| 计划刻/流体 | 主线程 | worlds 内已随世界并行 | 同上 | — |
| POI 扫描（村民/蜜蜂） | 逐实体重复扫描 | **可以** | 冻结视图批量提交计算池 | 低 |
| 爆炸射线 | 主线程 | 可但严格门控 | 固定子种子派生 + 原序合并；TNT 装置 bit-exact 不达标即放弃 | 高（生电红线） |
| 实体区域化 Tick | worlds 粒度已并行 | 单世界内需 R3 | 连通分量区域 + intent 化跨区效果 | 高（需对拍 0 分叉门禁） |

## 三、下一批开发顺序（beta7）

1. **L0 存档序列化下线程**（低风险先行）：自动保存尖峰直接受益，不改游戏逻辑；验收=崩溃注入+重启逐字段比对+保存窗口 MSPT。
2. **M1 陆地寻路快照**（旗舰项）：复用 beta5 水中寻路全部框架与测试矩阵，扩展陆地冻结清单；`async.pathfinding.land-snapshot` 默认 false。
3. **M2 推挤完整并行**（experimental）：`parallelism.entity-push-resolution` 默认 false；对拍=串行逐对一致。
4. **L1 POI 冻结视图**（低风险）：村民找工作/蜜蜂归巢批量提交。
5. **R3 区域模型原型**（不承诺）：连通分量划分器 + intent 化跨区伤害/传送，先在固定种子世界对拍。

## 四、执行纪律（延续）

每项：experimental 默认关 → 对拍框架逐项一致 + 全量回归 0 失败 → 真实服 soak 一个 beta → 连续两版零回退才评估默认开启。任何一项不满足即整项回退。
