# LeavesX 1.1.1-beta4

本版本仅适用于 Minecraft 26.1.2，重点加固异步区块编码、连接发送队列和异步任务关闭流程。

## 本版本内容

- 区块节编码成功和失败均进入明确的终态，避免编码失败后发送队列一直等待。
- 后台编码失败或任务取消时，最多重新编码一次完整副本；不拼接半成品，也不无限重试。内存耗尽等严重错误不触发普通重算。
- 永久编码失败由正常的数据包编码错误路径处理，普通编码异常不会直接穿透连接队列的就绪检查。
- 等待编码完成时不持有发布锁，避免一个连接的等待阻塞另一个连接检查同一份区块数据。
- 发布完成或失败后释放区块节快照和任务引用；同一个共享区块包不会因为一个连接清队列就被全局取消。
- 异步任务关闭时，先停止接收新的有序任务，再排空已接收任务。超时或中断不直接丢弃已排队的保存任务，也不允许新线程池越过旧任务执行。
- `/leavesx network` 增加区块节编码请求、发布、失败重算、永久失败统计，以及编码线程活跃数、排队数、同步回退和拒绝数。GUI 网络悬停信息同步增加编码统计。
- 修正异步区块发送启动提示，明确工作线程只编码区块节副本；光照、方块实体、插件事件及真实发包保留原有线程路径。
- 发布冒烟脚本同时支持内嵌服务端 JAR 和 Leavesclip 补丁式产物。对后者校验还原后的服务端 SHA-256 和 Manifest 版本，保留每轮标准输出与错误输出。

## 配置与诊断

相关开关仍为 `async.chunk-send.enabled`，默认关闭；本版本不强制覆盖现有配置。反矿透保持原路径。

控制台使用 `leavesx network`，游戏内使用 `/leavesx network` 查看网络统计。

“编码发布”表示字节已准备好，不代表客户端已接收。累计请求减去发布数不能作为队列长度；线程池排队和连接发送队列需要分别查看。Paper 原有即时发送例外保留，不将所有数据包改为全局严格 FIFO。

## 验证范围

- 网络回归覆盖并发读取、编码失败重算、永久失败、结果长度错误、任务取消、引用释放、发送顺序及共享包断连场景。
- 三轮隔离实例启动、诊断命令、只读配置检查、重载、命名实体跨重启保存、存档刷新及正常停服验证通过。

这是测试版本。自动化测试不能代替真实玩家、插件组合及弱网压力测试；没有据此宣称固定性能提升或完全无故障。更换服务端前请备份世界、插件和配置。
