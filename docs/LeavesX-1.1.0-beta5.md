# LeavesX 1.1.0-beta5

适用 Minecraft 26.1.2，Java 25。本版增加水中导航的完整后台路径搜索，沿用 Paper/原版 A* 和邻居访问顺序。多个生物的搜索使用独立数据，可同时执行；完整 Brain、陆地和飞行寻路仍未异步化。

## 使用

在现有 `leavesx.yml` 的对应位置修改，勿重复添加 `async` 节点：

```yaml
async:
  pathfinding:
    enabled: true
    water-snapshot: true
```

`water-snapshot` 默认关闭，可用 `/leavesx reload` 修改。计算池的 `enabled`、线程数和队列容量仍需要重启。配置版本更新为 80，旧值保留，不另建迁移报告或备份文件。

这是实验性选项：导航可能延后一刻或数刻开始移动；立即读取路径内容的 AI 或插件仍可能等待计算完成。因此不能保证所有装置时序完全不变，也不能保证小规模寻路一定更快。

## 计算边界

1. 主线程执行 `EntityPathfindEvent`，检查目标和世界边界，复制已加载区块段的压缩方块数据，记录生物体型、起点和寻路代价。
2. 工作线程只读取独立副本，执行水中节点分类及完整路径搜索，不读取或修改真实 Mob、Chunk、Brain 或 Bukkit 对象。流体标签分类也在提交前冻结。
3. 主线程采用结果前检查请求归属、生物状态和搜索实际读过的方块。数据包标签改变也会使旧分类失效。
4. 生物被移除、导航停止或请求被替换时，不再采用旧请求。地形或起点变化、搜索越界、计算异常时，用原算法完整重算，不拼接半成品节点。

适配精确的 `WaterBoundPathNavigation`、`SwimNodeEvaluator` 和 `PathFinder`。自定义子类、其他导航类型和开启寻路调试采集的请求保持原流程。即使生物身处水中，若它使用陆地或两栖导航，也不会自动套用这套算法。

快照范围为起点周围 49×49×49 方块，最多涉及 64 个区块段。范围边缘不是障碍墙；搜索需要越界读取时整条退回原搜索。最多同时准备或计算 16 个快照，名额或队列不足直接同步计算；这不是实体数量上限，也不会删除或冻结生物。区块未加载或调色板过大时同样使用原流程，不为准备快照加载新区块。

快照复制压缩存储而不是逐方块展开；路径完成后，仅保留实际读取位置用于复核。仍有复制、分配、排队及校验成本，是否提高 TPS 取决于场景。

## 插件与生电兼容

Paper 插件寻路接口仍同步返回完整路径或 `null`，不向插件返回尚未确定是否有路的结果。事件在主线程执行，可以正常取消。公开节点列表和路径访问方法均读取已采用的结果。

村民恐慌、刷铁、TNT、红石和实体存档不接入本次后台寻路。完整 AI 行为、攻击、移动及插件事件仍在主线程执行，本版不等同于 Folia 的区域 Tick。

## 诊断

`/leavesx threads` 显示寻路线程任务与水中快照计数：提交、采用、状态变化重算、越界重算、繁忙回退、快照不可用、异常重算和过期取消。快照计数自启动累计；共享池活跃数不能直接当作寻路并发数。

只有打开 `water-snapshot` 并产生符合条件的水中导航请求，才会增加后台寻路计数。陆地生物多的服务器仍可能主要使用单核，不能用本版结果推断所有生物 AI 已并行。

## 验证范围

自动化测试比较原算法与快照算法的目标、可达性、节点顺序及代价，覆盖水面、障碍、无路、多目标、负坐标、体型和代价差异；另测过期取消、地形失效、内存名额用完、异常回退及线程归属。Paper API 单独检查失败请求返回 `null` 和公开节点列表的一致性。

构建和真实服验证记录保存在 `build/reports/beta5`。这些检查不能代替生产存档、实际插件组合和生电装置的长期回归；未进行与 Folia 的同负载性能对比，不承诺性能提升百分比。

本轮全套回归 9,584 项，0 失败、22 跳过；随后补强标签冻结及 Paper 接口后，552 项 LeavesX 测试全部通过，其中包含新增的 16 项测试。11 个补丁涉及文件通过反向检查及隔离重新应用比对。

真实服完成开启、关闭后重启、缺省值补全后重启三轮。开启时 8 个请求全部后台完成并采用，逐节点与原算法一致；关闭后后台提交为 0。三轮均通过事件取消、命名实体保留、配置重载、存档和关闭检查。TNT 探针生成 30 个实体，初速度、首 Tick 和爆炸触发通过，保留 10 个源 TNT 方块；爆炸由探针取消以保护结构，未覆盖所有 TNT 炮。
