# LeavesX 1.1.1-beta4-recipe1

Minecraft 26.1.2 配方协议测试构建，基于当前 beta4 工作区。保留原 beta4 产物，不作为正式版发布。

## Just Enough Items（JEI）

在 `leavesx.yml` 已有 `features` 节点下增加以下配置。两个功能默认关闭，可分别开启；重载配置后重新进服。

```yaml
features:
  just-enough-items:
    # 同步服务端配方到 Just Enough Items（JEI）。
    recipe-sync: false
    # 允许 Just Enough Items（JEI）填充已解锁的合成与熔炉配方。
    recipe-transfer: false
```

- 配方同步根据客户端注册的 Fabric 或 NeoForge 配方通道发送，不按客户端品牌猜测协议；每次配方重载后重建缓存。
- 支持原版背包合成、工作台、熔炉、烟熏炉、高炉的材料填充。不支持酿造、切石、锻造、自定义机器或插件虚拟菜单。
- 由服务端根据实际物品和已解锁配方重新检查请求，通过配方书流程摆放材料；保留 Paper/Bukkit 配方书事件和插件取消行为。
- 转移前检查菜单、槽位、物品数量和玩家状态，事件返回后再次检查；满背包时不通过掉落物清空合成栏。
- 不开放 JEI 作弊取物和删除物品。带数量的转移请求目前仅接受每个操作数量为 1；最大填充由原版配方书计算。
- 仅同步使用已注册原版序列化器的配方，不保证自定义序列化器和所有 CraftEngine 配方兼容。
- 配置版本由 81 升至 82，迁移保留已有设置。

## Roughly Enough Items（REI）

继续使用 `leaves.yml` 的 `settings.protocol.rei-server-protocol` 开关。

- 修复分片收发中的缓冲区释放问题；限制未完成分片数量、大小和有效期，退出及关闭协议时清理缓存。
- 修复旧配方编码任务在重载后覆盖新缓存的问题。主线程构造配方显示数据，工作线程编码，回到主线程发布时校验版本。
- 拒绝重复、越界、重叠和无权限槽位，拦截将熔炉输出槽伪装为输入槽的请求。
- 转移执行前重新校验菜单和槽位权限，避免关闭菜单后继续操作旧容器。
- 材料扣除前检查目标物品、接收权限和堆叠容量，修复会丢失或错误转换物品的边界情况。

Leaves 自定义协议入口也调整为先切换至服务端线程，再执行涉及菜单和背包的处理。
